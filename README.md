# 植生野帳（Vegetation Relevé Notebook）

Braun-Blanquet法（植物社会学的手法）による植生調査を、**現場での記録から植生表・群落区分・遷移予測・現存植生図の作成まで**ひとつのアプリで行うためのWebアプリ（PWA）です。ビルド不要の静的ファイルだけで動き、GitHub Pagesで公開すればスマートフォンにインストールして**圏外でも**使えます。

## 主な機能

| 段階 | 内容 |
|---|---|
| 調査区の設定 | 群落の種類ごとの面積の目安（草原1〜25 m²、森林100〜500 m² など）を表示し、範囲外なら警告 |
| 環境情報 | 調査日・地点・緯度経度（端末のGPS）・標高・傾斜・方位・微地形・土壌・湿り・人為的影響・攪乱後年数 |
| 階層構造 | 高木層・亜高木層・低木層・草本層・コケ層ごとに高さ・植被率、優占種を自動表示 |
| 被度・群度 | Braun-Blanquet 7段階（r, +, 1〜5）または5段階、群度1〜5。片手で押せる大きなボタン |
| 植生表 | 素表 → UPGMAクラスタリングで群に区分 → 識別種（φ係数）を抽出して並べ替えた区分表、常在度表、樹形図。CSV出力・印刷 |
| 群集の判定 | 都道府県と標高から植生帯（亜熱帯／暖温帯／冷温帯／汎針広混交林／亜高山／高山）と日本海側・太平洋側を推定し、その地域の群集参照DBと照合 |
| 遷移予測 | 現在の遷移段階を推定し、管理シナリオ（放置／草刈り継続／皆伐後／シカ高密度）ごとに年数に応じた到達植生と極相候補を表示 |
| 植生図 | 調査区を判定結果や植生表の群で色分けして地図に表示し、植生区画を描いてGeoJSONで出力（QGIS等で利用可） |

## 公開方法（GitHub Pages、スマホのみで可）

ファイルはすべて同じ階層にあり、フォルダはありません。

1. GitHubアプリではなく、ブラウザで github.com を開いて新しいリポジトリを作ります（Public、README追加にチェックを入れておくと空でなくなり操作しやすくなります）。
2. リポジトリのトップで「Add file → Upload files」を選び、次の7ファイルをまとめて選択してアップロードし、「Commit changes」を押します。
   `index.html` `sw.js` `manifest.webmanifest` `icon-192.png` `icon-512.png` `icon-maskable-512.png` `LICENSE`
   （README.md は手順1で作ったものをこのファイルで上書きしても、そのままでも構いません）
3. 「Settings → Pages」で Source を「Deploy from a branch」、Branch を `main`、フォルダを `/ (root)` にして「Save」。
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます。

スマホのブラウザで「Upload files」が見つからない場合は、ブラウザのメニューから「PCサイトを表示」に切り替えてください。

## オフラインで使うには

- **出発前に一度オンラインでアプリを開いてください。** アプリ本体と地図ライブラリが端末に保存されます。スマートフォンではブラウザの「ホーム画面に追加」でアプリとして起動できます。
- **背景地図**は、オンライン時に表示した範囲のタイルが保存され、圏外でも再表示されます。調査予定地を事前にいくつかの縮尺で表示しておくと安心です。
- 次の機能だけは通信が必要です：国土地理院APIによる標高・都道府県の自動取得、未表示範囲の地図タイル。
- GPSによる位置取得は圏外でも使えます。

## データの保存

記録はブラウザ内（localStorage）に保存されます。ブラウザのデータ消去やアプリの削除で失われるため、**調査のたびに「設定 → バックアップを書き出す」**でJSONを保存してください。別の端末へは同じ画面の「バックアップから復元」で移せます。全記録は縦持ち形式のCSVでも出力できます（R・Excel・JUICE等への取り込み用）。

## 解析の方法

- **類似度**：Bray-Curtis距離（被度階級の中央値〔r=0.1, +=0.5, 1=5, 2=17.5, 3=37.5, 4=62.5, 5=87.5%〕の平方根）または Jaccard距離（在・不在）。
- **区分**：UPGMA法の樹形図を指定した群数で切断。群を手動で指定することもできます。
- **識別種**：群内の出現頻度が閾値（既定50%）以上、群外の出現頻度35%以下、φ係数が閾値（既定0.3）以上の種。1群だけに偏る種と複数群に共通する種を分けて表の上部に並べ、残りを随伴種として頻度順に並べます。
- **常在度**：I（≤20%）〜V（>80%）と被度の範囲。
- **群集の判定**：参照DBの標徴種・優占種（重み3）、識別種（1.5）、随伴種（0.5）の一致度に被度を加味し、植生帯・地方・日本海側／太平洋側の整合度を掛けた値で順位付けします。

## 遷移予測の考え方

植生帯ごとに、一年生草本 → 多年生草本 → ススキ・ササ草原 → 先駆性低木林 → 陽樹二次林 → 遷移後期林 → 極相林の各段階の標準滞在年数（早い／標準／遅い）を持ち、次の要因で速さを補正します。

- 下層（亜高木・低木・草本層）に極相構成種が多い → 速まる
- ササ類・クズ・コシダなどが低木層・草本層で被度4以上 → 停滞
- 乾性・未熟土・尾根 → 遅れる（アカマツ林などの土地的極相に留まる可能性）
- 急傾斜 → やや遅れる
- 湿地は湿地系列（ヨシ → ハンノキ林）、海岸砂丘は海岸系列として扱います

年数は一般的な知見にもとづく**目安**です。種子供給源との距離、シカの密度、気象害などで大きく変わります。

## 群集参照DBの拡張

内蔵DBは全国の代表的な群集・群落（約40）を代表種で記述した**簡易版**です。地域の植生誌にもとづく群集は、「設定 → 現在のDBをJSONで書き出す」で得られる形式に合わせて追加できます。

```json
{
  "format": "vegsurvey-syntaxa-1",
  "syntaxa": [
    {
      "id": "my-association",
      "ja": "〇〇－△△群集",
      "la": "Xxx-Yyyetum zzz",
      "cls": "ヤブツバキクラス",
      "type": "climax",          // climax | substitute | pioneer | edaphic | plantation
      "stage": 7,                // 0〜7（遷移段階）
      "zones": ["WE"],           // ST | WE | CD | MX | SA | AL
      "regions": ["四国", "九州"], // 空配列で全国
      "sea": "",                 // J（日本海側）| P（太平洋側）| ""
      "char": ["標徴種1", "標徴種2"],
      "diff": ["識別種1"],
      "comp": ["随伴種1"],
      "note": "立地などの説明"
    }
  ]
}
```

（実際のJSONにはコメントを書かないでください。）都道府県ごとの植生帯境界標高も「設定」で調整できます。

## ファイル構成

```
index.html             アプリ本体（画面・スタイル・解析処理・群集参照DBをすべて含む）
sw.js                  オフライン対応（サービスワーカー）
manifest.webmanifest   ホーム画面に追加するための情報
icon-192.png ほか      アプリアイコン
```

群集参照DBや植生帯の境界を直接書き換えたい場合は、index.html 内の `data.js` の部分（`VEG.SYNTAXA`、`VEG.PREFS`）を編集します。アプリ内の「設定」からJSONで追加することもできます。

アプリを更新したときは `sw.js` の `VERSION` を変えると、利用者の端末のキャッシュが新しい版に入れ替わります。

## 注意

群集名・標徴種は代表的な例であり、報告書・論文で群集を確定する際は、各地域の植生誌、原記載、環境省自然環境保全基礎調査（植生調査）の凡例と必ず照合してください。

背景地図と標高・住所の取得には[国土地理院](https://maps.gsi.go.jp/development/ichiran.html)のサービス、地図表示には [Leaflet](https://leafletjs.com/) を利用しています。
